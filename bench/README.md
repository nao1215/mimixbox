# Benchmarks

mimixbox is measured the way a shell runs an applet, one process per call from start to exit, with [himorime](https://github.com/nao1215/himorime). himorime builds mimixbox, runs each command in interleaved rounds, and reports latency, CPU time, peak RSS and, for the large inputs, throughput.

```console
$ go install github.com/nao1215/himorime@latest
$ make bench            # himorime run bench
$ make bench-compare    # himorime compare --against main bench
```

## Regression suite: himorime.yaml

`make bench-compare` checks main out into a temporary Git worktree, builds it and your working tree, and measures both in the same rounds, so a background job slows both revisions instead of one. `BASE=v0.42.6 make bench-compare` compares against another revision. `himorime run --filter 'sort 100k' bench` measures one benchmark.

On a pull request, `.github/workflows/bench.yml` runs `himorime ci bench` the same way, with the base of the pull request as the base, on one runner. The job fails when a command is slower, uses more CPU time or more memory than the base beyond the tolerance in `himorime.yaml` with 95% confidence. A difference too close to call is reported as inconclusive and does not fail the job.

The inputs are generated by `gen.sh` before measuring, so no fixture is committed, and both revisions run the working tree's `gen.sh`.

| Benchmark | Commands | Measures |
|-----------|----------|----------|
| `version` | `mimixbox --version` | starting mimixbox, which every applet call pays |
| `sort 10` | `cat`, `sort`, `wc -l` of ten lines | the applets that read lines, where start-up dominates |
| `sort 100k` | the same on 100,000 lines | reading and sorting, with throughput in lines per second |
| `ls 10` | `ls -l -i --sort=size` of ten files | listing a small directory with a stat of every entry |
| `ls 500` | the same of 500 files | listing a large directory; this was the `testing.B` benchmark of ls |
| `cat error` | `cat` of a missing file | the failure path, exit 1 |

The applets that need root, a terminal or the network (`mount`, `ping`, `top`) are not measured: a runner cannot give them the same conditions on every round.
